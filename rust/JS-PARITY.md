# JavaScript parity notes

The v0 runtime is a structural translation of the corresponding parts of `src/core.ts`,
`src/serialize.ts`, and `src/rpc.ts`. Rust source keeps JavaScript class names and method names where
possible. Every implemented method with different behavior has an inline `Difference from JS:`
comment.

## Mechanical language mappings

These apply throughout and are not repeated on every method:

| JavaScript                              | Rust                                             |
| --------------------------------------- | ------------------------------------------------ |
| `unknown`                               | `CapnwebValue`                                   |
| `StubHook` object reference             | `Arc<dyn StubHookInner>`                         |
| abstract `StubHook` class               | `StubHookInner` trait                            |
| `RpcPayload \| Promise<RpcPayload>`     | `MaybePromise<RpcPayload>`                       |
| thrown exception                        | `Result<T, Error>` or `ErrorStubHook`            |
| eager `Promise<T>`                      | eagerly spawned `EagerPromise<T>`                |
| `instanceof` on a hook                  | `Any` downcast at the one `getImport()` seam     |
| `Proxy` call/property interception      | generated methods from `#[rpc_interface]`        |
| `RpcTarget` prototype reflection        | dispatch generated by `#[rpc_target]`            |
| explicit local hook refcounts           | `Arc`, ownership, and `Drop`                     |

## Implemented parity slice

### `core.ts`

- `StubHook.call()`, `get()`, `pull()`, and `dup()`
- `ErrorStubHook`
- `TargetStubHook`
- `PayloadStubHook`
- `PromiseStubHook`
- `RpcPayload.fromAppParams()`, `fromAppReturn()`, and recursive delivery
- `RpcStub` and `RpcPromise` call/pull behavior
- the central `doCall` seam used later by `.map()`

### `serialize.ts`

- contextual `Exporter` and `Importer` interfaces
- `Devaluator` for null, booleans, numbers, strings, arrays, objects, targets, stubs, and promises
- `Evaluator` for the same value slice
- `import`, `pipeline`, `export`, `promise`, and error expressions

### `rpc.ts`

- `ImportTableEntry`
- `RpcImportHook`
- import and export tables
- positive push IDs and negative exported-reference IDs
- `push`, `pull`, `resolve`, `reject`, `release`, and `abort`
- eager promise export resolution and root promise-chain elision
- in-memory, newline-delimited I/O, and WebSocket string transports

## Intentional v0 omissions

These source areas have not been translated yet rather than replaced with new abstractions:

- the wire-level `StubHook.map()` instruction protocol from `map.ts` (Rust currently has a
  pull-then-map compatibility fallback)
- stream calls, `pipe`, readable/writable expressions, and `streams.ts`
- typed-array identity, headers, request, response, blob, and rich errors
- HTTP batch transport
- numeric property-path components on the wire
- full session abort propagation and all rollback paths
- loopback defensive-copy details which Rust ownership may make unnecessary

The omission list is the next translation queue. New runtime concepts should not be introduced for
these features until the corresponding JavaScript implementation has been translated and its Rust
language differences documented.
